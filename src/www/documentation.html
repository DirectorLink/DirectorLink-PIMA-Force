DirectorLink · PIMA FORCE

Free, open-source Control4 driver for PIMA FORCE alarm panels (FORCE, FORCE 32C, FORCE 16) using the panel's local JSON interface. No cloud and no extra hardware: the panel connects over the LAN to this driver, the same way it connects to a monitoring station. Part of DirectorLink Drivers: directorlink.io/drivers/pima-force (help, updates and the source).

Panel firmware. The JSON interface is not in every FORCE firmware. Panels on older firmware (for example 1.5.x) must be upgraded first: Master code → Communication → Remote Service → Upgrade/Update → Firmware: Latest version → Over Network, or ask your installer / PIMA support for firmware with the Smart Home (JSON) interface. After the upgrade, a CMS network path offers Protocol = JSON and Users & Codes shows a Smart Home code.

1. Panel setup (installer code)

Installer code → System Programming → CMS & Communication → Monitoring Stations → CMS 2 (or 3) → Comm. Paths → Network (Ethernet). Never reuse a CMS that reports to a monitoring company.

In the user menu enable Remote Disarm, otherwise the panel refuses disarm commands from Control4.

Zones appear in the Security Panel's zone list with the names stored in the panel. Rename them or set their type (door, motion, smoke...) in the panel proxy's Zones page. Each zone also has a Zone N contact connection: bind a Control4 contact driver (Door Contact, Motion Sensor...) to it to use the zone in rooms and programming.

3. How it behaves

  • Arm (Away = Full arm, Home = Home 1, Night = Home 2). After the panel accepts, Navigator shows the exit delay countdown, then the driver reads the panel to confirm the arm. If zones are open the panel refuses and Navigator offers to bypass them.
  • Disarm from Navigator always needs a code. The code is sent to the panel, which checks it. Programming disarms with the Panel User Code.
  • Alarms (burglary, fire, panic, medical, duress) put the partition in Alarm until it is disarmed.
  • Troubles come from the panel's fault list (AC loss, low battery, tamper, communication...) and appear on the Security Panel. Losing the connection adds a Communication with panel lost trouble.
  • Events for programming: Communication Lost / Restored, Siren Active / Inactive, Access Denied, plus the standard partition events (Armed, Disarmed, Alarm...).
  • Commands for programming: Bypass Zone, Unbypass Zone, Activate Output, Deactivate Output (controlled outputs 1-8).
  • Panic / fire / medical buttons are not offered: the PIMA protocol cannot trigger them.

3a. Receive-only mode (firmware without JSON)

If the panel's CMS path offers no JSON protocol, leave it on its normal alarm-report protocol (SIA DC-09, Contact-ID or SIA codes, encryption off). The driver detects it, acknowledges every report and switches to receive-only mode. Connection Status then reads Receive only (SIA DC-09): last report ....

  • Shown: armed (Away / Home) and disarmed, alarms, troubles, siren, and zone open/close when the panel reports it.
  • Not possible: arming, disarming, bypass and outputs from Control4; zone names (rename zones in Composer).
  • The partition state is unknown until the panel sends its first arm or disarm report. Arm and disarm once at the keypad after installing.
  • Zones are added as the panel reports them. Set Zone Count to create them all at once.
  • Turn on the CMS path's life signal: the driver learns its interval and adds a communication trouble when it stops.
  • When JSON firmware is installed later, set the CMS path to JSON: the driver switches to full control by itself.

3b. DirectorLink

The partitions are Control4's standard security partitions, so any Control4 app shows them. In DirectorLink (with its Alarm Status property On) the DirectorLink app shows each partition's state on Home. From DirectorLink 1.15.0, with its Alarm Control property On, people you allow can also arm and disarm from the app: they type their alarm code each time, it goes to the panel as typed and the panel checks it. This driver never arms or disarms for DirectorLink with the Panel User Code.

The driver tells DirectorLink when arming and disarming can work, in the variable DIRECTORLINK_ALARM_CONTROL: 1 with the JSON interface connected, 0 in receive-only mode or without a panel connection (DirectorLink then shows the state only). DIRECTORLINK_ALARM = 1 says the driver follows DirectorLink's alarm agreement. DirectorLink is not required: without it the driver works the same.
